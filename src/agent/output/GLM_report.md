## 0. 结论摘要（先给判断，再给证据）

### 0.1 一句话结论

> **现金流质量评级：结构性未自给，方向性在改善，证据链不完整。**

- **正面**：成长引擎（开放平台及 API）的单位经济由负毛利修复至正毛利（约 **−0.4% → 24.6%**）；API 平均售价上调约 **101%**（非以价换量）；收入结构从「项目制垫款」转向「按量调用/订阅预付」，机制上有利于回款前置；付费日活较年初 **+603%**，远快于总用户 **+144%**。

## 3. 收入结构与现金转换：本报告最有价值的一条分析链路

### 3.1 交易形态演进 → 现金时点的映射

公司自述的交易形态演进为「**卖模型 → 卖调用 → 卖订阅 → 卖端到端任务结果**」（p.21）。公司只讨论了每种形态的**能力门槛与市场空间**，**完全没有讨论其对现金时点的影响**。这是本报告补充的关键分析：

| 交易形态 | 收入确认 | 收款时点（机制）【推断】 | 对经营现金流方向 | 2026H1 收入占比【原文】 |
|---|---|---|---|---:|
| 卖模型（本地化部署、一次性授权） | 项目验收/交付时点 | **滞后**：项目制、验收长、机构账期长，形成应收 | 现金**落后**于收入，需垫营运资金 | **13.5%**（去年全年 73.7%） |
| 卖调用（开放平台/API，按量计费） | 随 Token 消耗 | **前置或同步**：行业惯例为充值/预付余额，消耗时确认 | 现金**领先**于收入，形成合约负债 | **86.5%**（去年同期 15.2%，p.22） |
| 卖订阅（GLM Coding Plan） | 订阅期内分摊 | **最前置**：预付整期费用 | 强正向 | 极小（2026 年 8 月才对全量开放，p.13） |
| 卖端到端任务结果（Co-work） | 任务交付/里程碑 | 未披露 | 未知 | 尚未规模化（p.15、p.22） |

**【推断】这条置换在机制上把「收入→现金」的时滞由正（垫款）翻转为负（预收），是现金流质量的结构性利好。** 但报告期内**可验证的量化证据为零**：公司未披露预收款/合约负债余额、API 账期政策、应收款项明细。

### 3.2 结构置换的绝对额含义【测算】（三重勾稽已通过）

- 2026H1 开放平台及 API 收入 = 953,892 × 86.5% = **825,116（约 8.25 亿）**【与 p.14「约 8.25 亿人民币」✅ 勾稽】
- 2025H1 API 收入 = 190,877 × 15.2% = **29,013（约 0.29 亿）** → 8.25 / 0.29 ≈ **28.5 倍**【与 p.14「同比增长 2,735.7%」= 28.357 倍 ✅ 勾稽】
- 2026H1 本地化部署 = 953,892 × 13.5% = **128,775（约 1.29 亿）**
- 2025H1 本地化部署 = 190,877 − 29,013 = **161,864（约 1.62 亿）**
- ⇒ **高毛利、慢回款业务绝对额同比下降约 20.4%**

**定性解读的双向性**（这是本次结构变化最容易被单边解读的地方）：
- **利好现金流质量**：退出账期最长、验收最慢的项目制收入，理论上应收占用下降、收入变现速度提升。
- **利空当期损益**：同时退出了毛利率最高的收入（本地化部署隐含毛利率约 59%，见 §4.2），短期毛利绝对额与经营杠杆被压缩。
- 且这是**主动收缩**，非被动丢失：「本公司在這一階段**主動收縮**了本地化部署模型軟件授權業務」（p.21）。

### 3.3 MD&A 中「现金流」三个字的缺席（重大定性信号）

通读 p.13–29 完整 MD&A 前半，**全文没有任何一句讨论经营活动现金流、现金消耗、资金余额、烧钱速度或融资安排**。公司用于自我证明「造血」的替代指标是：

> **【原文·p.22】**「報告期內，本公司的算力乘數－每投入人民幣1元算力（含訓練與推理）所對應的開放平台及API收入－較去年同期提升約14倍。……每投入人民幣1元算力換回的收入在增加，意味著模型的自我造血能力在增強。」

**【关键风险点】**「算力乘数」= **收入 ÷ 算力投入**：分子是收入（非现金流入），分母是算力投入（含非现金折旧与资本化支出，口径未披露）。这是一个**收入效率指标，不是现金效率指标**。即使算力乘数提升 14 倍，只要毛利小于研发加资本开支，现金仍为净流出。**将该指标解读为「自我造血能力增强」，属于管理层对指标口径的拉伸**，投资者不应据此推断现金流转正。

## 4. 单位经济性的正确读法（含关键口径修正）

### 4.1 「毛利率腰斩」不等于「单位经济恶化」——必须分业务看

**这是本报告必须明确的第一个口径修正。**

| 层面 | 数据 | 方向 |
|---|---|---|
| 合并毛利率 | 50.00% → 26.37%（−23.63pp） | 恶化 |
| **成长引擎（开放平台及 API）** | 约 **−0.4%**（2025H1）→ **18.9%**（2025 全年）→ **24.6%**（2026H1） | **显著改善** |
| 本地化部署（隐含）【测算，置信度中低】 | 约 **59%** → 约 **37.8%**（−约 21pp） | 恶化 |

**毛利率链的三重勾稽**（全部通过）：
- 18.9% + 约 6pp ≈ 24.9% ≈ **24.6%**【原文 p.21、p.22】
- 24.6% − 约 25pp ≈ **−0.4%**（即一年前 API 业务**毛利为负**）【原文 p.22 + 测算】
- 隐含本地化部署毛利率：2025H1 = 95,424 / 161,864 ≈ **59.0%**；2026H1 = (251,611 − 825,116 × 24.6%) / 128,775 ≈ 48,632 / 128,775 ≈ **37.8%**

**正确表述方式**：
> 合并毛利率下滑 −23.6pp，主要由「主动收缩高毛利本地化业务（绝对额 −20.4%）+ 收入结构下沉（86.5% 收入来自毛利率 24.6% 的业务）」共同造成；成长引擎本身的单位经济是**明确改善**的。真正需要担心的是**绝对毛利额（2.52 亿）与研发投入（21.31 亿）之间 8.5 倍的缺口**，而非毛利率这个比率本身。

**对现金流质量的实质含义**：API 毛利率由负转正 + 售价上调 101%，说明公司**不是靠降价换量**——这一点是重要的正面证据（以价换量通常伴随放宽信用政策与应收膨胀）。但 §4.2 的本地化毛利率下滑尚有未解释部分，需提示为待查项。

### 4.2 本地化部署隐含毛利率下降 21pp 的三种解释（原文均未说明）

| 解释 | 机制 | 对现金流质量的含义 |
|---|---|---|
| (a) 推理算力成本从研发/其他科目**重分类**入营业成本 | 不改变现金，但抬高营业成本、压低研发费用 | 使「研发 21.31 亿」口径虚高，研发/亏损的因果归因需打折 |
| (b) 国产芯片/算力资产**折旧摊入成本** | 非现金成本 | 若成立，OCF 会**优于**净亏损（对现金流质量是正面） |
| (c) 部署项目端价格竞争加剧 | 单价下行 | 对现金与毛利均为负面 |

**因此，本报告对「研发 21.31 亿 ≈ 税前亏损 103%，亏损几乎完全由研发构成」这一说法作打折处理**：更严谨的表述是「**研发投入与亏损处于同一量级（研发约 21.31 亿、税前亏损 20.70 亿），亏损主要由研发驱动的可能性高，但研发口径可能因成本重分类而虚高**」。这是本报告采纳的第二项口径修正。

其余项目反推【测算，误差 ±数千万，因研发为「约」数】：2,131 − 251.6 − 2,070.0 = **−190.6（百万）**，即销售+行政+其他收益净额合计约 **1.91 亿元净费用**。

## 5. 亏损质量：报表亏损 vs 经调整亏损（本次分析的第一个红旗）

| 项目 | 2026H1 | 2025H1 | 变动 |
|---|---:|---:|---:|
| 期内亏损（IFRS） | (2,071,992) | (2,357,852) | 收窄 12.1% |
| 经调整净亏损（非 IFRS） | (1,964,138) | (1,751,974) | **扩大 12.1%** |
| **差额（非 IFRS 调整项）** | **107,854** | **605,878** | — |
| 差额占亏损比 | **5.2%** | **25.7%** | −20.5 pp |

**解读**：
- 2025H1 报表亏损比经调整亏损多 6.06 亿（25.7%），此类大额调整通常为**优先股公允价值变动等非现金项目**；
- 2026H1 该差额骤降至 1.08 亿（5.2%），与 **2026-01-08 上市后优先股由负债重分类为权益、公允价值变动消失**的结构一致【推断，与 §6 权益变动桥互相印证】；
- **含义：2026H1 的 20.72 亿亏损「含非现金水分」大幅减少，即更接近真实的经营性现金消耗。**

**管理层口径选择问题**：
> **【原文·p.22】**「本公司期內虧損較去年同期減少12.1%，虧損率（虧損╱收入）較去年同期收窄4.7倍，經調整期內淨虧損率……收窄3.5倍。」

MD&A 只陈述了 IFRS 口径的「亏损收窄」，**未同幅提示经调整亏损扩大 12.1%**；「亏损率收窄 4.7 倍」是**分母效应**（收入 ×5）而非分子改善（亏损绝对额仍为收入的 217%）。

**这是本次分析最重要的结论性纠偏**：
> 「账面亏损变好看 + 现金消耗变严重」同时成立。报表亏损收窄 12.1% **不构成**任何现金流改善的证据；若以现金流质量视角看，**本期比去年同期消耗更多**。

## 6. 资产负债表的修复来自融资，而非经营

### 6.1 权益变动桥【测算】

- Δ权益 = 4,429,556 − (−8,110,982) = **+12,540,538 千元（+125.4 亿元）**
- 其中：期内亏损 −2,071,992（−20.7 亿元）
- ⇒ **非亏损带来的权益增加** = 12,540,538 + 2,071,992 = **14,612,530 千元（+146.1 亿元）**
- 同期 Δ负债 = 5,215,274 − 12,964,843 = **−7,749,569 千元（−77.5 亿元）**
- Δ资产 = 9,644,830 − 4,853,861 = **+4,790,969 千元（+47.9 亿元）**
- 勾稽检验：**47.9 = 125.4 − 77.5** ✅ 完全闭合

**解读**：权益暴增 125.4 亿元中，约 **77.5 亿元与负债同额减少互补** → 极可能是**首次公开发售时可转换可赎回优先股由负债重分类为权益（纯会计、无现金）**；真正带来资产增量的约 **47.9 亿元**（Δ资产）。

### 6.2 资金需求的量级判断（简化表述）

以「Δ资产 47.9 亿 + 期内亏损 20.7 亿」计，合计约 **68.6 亿元**。此数字**口径较粗**（假设无其他全面收益、无营运资本释放、无非现金资产增加，属**上限**），本报告仅用它做**量级判断**：

> 该规模**在量级上指向一次大规模股权融资**，与「H 股 2026-01-08 上市」的募资体量相符。但**具体募资净额与所得款项用途在缺失的 p.40–52 中，本报告不作数字填补**。

### 6.3 关键反事实检验

- 若本期经营现金流为正，则 Δ资产 47.9 亿必须由「经营现金流入 + 融资」共同支撑；鉴于期内亏损 20.7 亿、研发与算力支出刚性强，**经营现金流为正的概率很低【推断】**。
- 若本期经营现金流为负（**基准假设，非事实**），则**全部资产扩张 + 全部亏损均由融资（IPO 募资 + 银行授信，主要往来银行：招商银行北京清华园科技金融支行，p.4）承担**。
- **续航粗算（极粗，仅作量级参考）**：权益 44.3 亿 ÷ 半年亏损 20.7 亿 ≈ **2.1 个半年（约 13 个月）**。该数字**严重高估**可用现金，因为权益中包含算力设备、使用权资产、应收款、预付算力款等非现金资产。**真实续航取决于 p.55 的现金余额与 p.60 的现金流出，目前缺失。**

> **本节核心结论：资产负债表修复 ≠ 现金流改善。** 权益由负转正、资产负债率由 267.11% 降至 54.07%，几乎全部由**非现金的会计重分类**与**外部股权融资**达成，与经营现金创造力无关。

## 7. All-in-Infra：改善成本线，恶化现金线（最容易被误读的一节）

**【原文·p.13】**「本公司自2026年初起全面實施All-in-Infra戰略，在訓練與推理兩側同時投入，並將國產芯片納入主力推理算力，已實現**10萬級國產芯片**的規模化低成本推理，**單位token推理成本較年初下降80%**。」
**【原文·p.20–21】**「端到端服務性能提升300％……技術上的主要約束是國產芯片的**內存容量與帶寬**……做了**以算力換帶寬、以通信換顯存**的定製優化。」
**【原文·p.20】**「在全球**算力供給持續緊張**的條件下，這條路徑決定了本公司的成本曲線掌握在自己手裡。」

**必须分开看的三件事**：

1. **成本下降是（部分）损益表事实**：单位 token 推理成本 −80% 支撑了 API 毛利率由 −0.4% 修复至 24.6%，**这是可现金化的改善**（每元收入消耗的算力现金减少）。
2. **但「成本曲线自主」是用资本开支买来的**：10 万级国产芯片、自研高带宽互联、SGLang 定制引擎、EPD 分离式推理架构 → **投资活动现金大幅流出 + 后续折旧摊销上升**。因此**自由现金流（OCF − Capex）大概率低于经营现金流，且为负【推断，Capex 数据缺失】**。
3. **一个反向的、可能利好 OCF 的机制（关键分叉）**：
   - 若国产芯片为**自购资产** → 成本以**折旧（非现金）**计入营业成本 → **OCF 会显著优于净亏损**（亏损的现金含量低，现金流质量相对改善）；
   - 若算力为**租用/外采第三方** → 属**现金经营支出** → **OCF 与净亏损接近**（现金消耗与亏损同步）。
   - 补充线索：**「以算力换带宽、以通信换显存」**（p.21）暗示用更多国产卡数量弥补单卡性能 → **单位算力的资本开支强度更高、折旧基数更大**；
   - 另一现金占用线索：算力供给紧张环境下国产芯片采购通常需**预付/长单承诺** → 体现为「预付款项/其他应收款」与「资本承担」，**均在缺失页**。

> **这是本次分析最需要裁决的分叉点**：同一份报告，「国产芯片大规模自建推理」既可能让 OCF 看起来远好于净亏损（折旧非现金），也可能让自由现金流崩塌（Capex 刚性）。**只有 p.55 + p.60 能裁决，当前不得只凭文字下结论。**

## 9. 现金流质量的三档情景框架与敏感性

### 9.1 三档情景（用于数据到手后的定性归类，非预测）

| 情景 | 触发条件（p.55/p.60） | 对现金流质量的解读 |
|---|---|---|
| **A｜好的负 OCF** | 合约负债增加额/收入 ≥ 10%；DSO 下降；折旧占比高（自购芯片） | 客户预付在为经营融资，亏损主要是非现金项；结构置换真实生效 |
| **B｜中性的负 OCF** | 合约负债小幅增长；DSO 平稳；Capex/收入 50%–100% | 增长靠融资与营运资本共同支撑，需持续外部输血 |
| **C｜坏的负 OCF** | 应收与预付款同步膨胀、DSO 上升、靠拉长应付账期支撑 | 增长靠放宽信用与占用供应商资金换取，收入质量差 |

**预置判定阈值**（数据到手后可直接执行）：
1. |OCF| < |经调整亏损| 的 **50%** → 亏损主要由非现金项构成，质量尚可；|OCF| ≥ |经调整亏损| 的 **90%** → 亏损几乎全额现金化，质量差。
2. 合约负债增加额/收入 ≥ **10%** → 「好的负 OCF」；反之靠应付账期上升支撑 → 「坏的负 OCF」。
3. Capex/收入 **>100%** → 扩张完全靠融资；**50%–100%** 重度投入；**<30%** 轻资产化转折信号。
4. 现金及等价物/月均经营现金流出 **≥12 个月** → 无短期融资压力；**<6 个月** → 需关注后续融资。
5. OCF 改善速度快于毛利改善速度 → 收入质量真实改善；OCF 恶化而毛利率企稳 → 增长靠放宽信用/降价换取。

### 9.2 敏感性（已按审稿意见修正数量级）

- 若下半年研发维持 21.31 亿/半年节奏、边际毛利率维持 20.47%，则**半年经营现金缺口量级约 17–19 亿元**（= 研发 − 毛利 ± 营运资本变动；营运资本项**缺失**）。
- **毛利率每下降 1pp，半年毛利减少约 0.095 亿元（约 954 万元）**（= 953,892 千元 × 1%）。对现金缺口的影响近似线性。
  > 说明：此处为本次审稿发现并已修正的数量级错误——原笔记误记为「0.95 亿元」，实际为「0.095 亿元 / 954 万元」，相差 10 倍。
- 盈亏平衡的量化门槛（**假设情景，非公司指引**）：保持研发 21.31 亿/半年、忽略其他费用：
  - 按边际毛利率 20.47%：所需半年收入 ≈ 2,131 / 20.47% ≈ **104.1 亿元**（当前 9.54 亿的 **10.9 倍**）；
  - 按当期毛利率 26.37%：所需半年收入 ≈ 2,131 / 26.37% ≈ **80.8 亿元**（当前的 **8.5 倍**）。
  - 该测算不含折旧随算力扩张的上升、不含股份支付，属**乐观口径**，仅用于刻画「经营现金流自给」的距离量级。

## 12. 总体评价与投资含义

### 12.1 三条可确认的判断

1. **经营层面尚未形成现金自给**：毛利 2.516 亿 vs 研发约 21.31 亿，缺口约 18.8 亿元量级；期内亏损 20.72 亿，其中经调整亏损 19.64 亿。即便按管理层最乐观口径（API 毛利率 24.6%、售价 +101%、算力乘数 +14 倍），**报告期内不存在任何一条证据表明经营现金流为正**。
2. **「亏损收窄」不可用于现金流论证**：IFRS −12.1% 与经调整 +12.1% 方向相反，非现金调整占比由 25.7% 降至 5.2% → **本期亏损的现金代表性上升，现金消耗实际加重**。
3. **收入变现机制正向「现金友好」方向重构，但验证数据全部缺失**：API/订阅占比 15.2% → 86.5%，本地化部署绝对额 −20.4%，机制上应从「垫款」转为「预收」；然而合约负债、应收、DSO 三项核心指标均落在 p.55/p.62，**无法验证**。

### 12.2 「改善潜力」与「现实缺口」必须分开陈述

- **改善潜力（定性成立，量化待验）**：卖出的是「更靠近结果」的东西，交易频次从一次性授权 → 按量调用 → 订阅预付，**客户预付可成为营运资金来源**；单位 token 推理成本 −80%（p.13）与国产芯片性价比赛道（p.21）若可持续，将降低每元收入的现金成本；**GLM Coding Plan 于 2026 年 8 月全量开放（p.13），首次把「预付订阅」变成主渠道之一，其现金效应在 2026H2 才可首次观测**。
- **现实缺口（定性 + 测算成立）**：研发刚性强（21.31 亿/半年）、算力 Capex 刚性强（All-in-Infra、10 万级芯片集群）、新方向尚未规模化收入 → 现金缺口需由 IPO 余款、银行授信与后续资本市场融资承接。

### 12.3 一句话评级

> **现金流质量：结构性未自给，方向性在改善，证据链不完整。**
>
> **正面**：成长引擎毛利由负转正（约 −0.4% → 24.6%）、售价上调 101%、付费日活 +603%、交易形态转向预收型、老业务主动收缩降低应收占用。
>
> **负面**：绝对亏损扩大（经调整 +12.1%）、毛利仅覆盖研发的 11.8%、算力 Capex 与折旧刚性上升、管理层以「算力乘数」等收入类指标替代现金类指标、MD&A 通篇未讨论现金流与流动性、资产负债表修复 100% 来自融资与会计重分类。
>
> **投资含义**：在缺失页（p.35–39 流动资金段、p.40–52 募资用途、p.55 资产负债、p.60 现金流量）取得前，对该公司现金流质量的判断应维持「**高度不确定**」。任何基于业务叙事（能力阶梯、算力乘数、Token 调用量、市场空间）推出的「造血已实现」结论均不成立。
